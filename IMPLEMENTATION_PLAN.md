# План реализации Telegram-бота «Склад»

План составлен по исходному ТЗ; он не расширяет продуктовый объем.

## Шаги

1. **Структура и запуск.** Создать `main.py`, `handlers/`, `database.py`, `keyboards.py`, `config.py`, `requirements.txt` и README с установкой, настройкой `.env` и запуском. Использовать Python 3.10+, aiogram 3, SQLite и асинхронную обработку.
2. **Настройки и доступ.** Читать токен и `ALLOWED_USERS` из `.env`; не хранить секреты в коде или Git. Запретить обработку функций для ID вне списка и отвечать «У вас нет доступа».
3. **Хранение и история.** Создать таблицы `products` и `operations` с полями из ТЗ. Нормализовать ключ названия регистронезависимо и с объединением лишних пробелов; хранить исходное отображаемое имя. Изменение остатка и запись операции выполнять в одной транзакции.
4. **Меню и диалоги.** На `/start` показать шесть кнопок главного меню. Реализовать пошаговые диалоги через FSM; `/cancel` отменяет диалог и возвращает меню. Нажатие кнопки меню внутри диалога начинает выбранный сценарий. Неподходящий тип сообщения внутри диалога не сбрасывает состояние.
5. **Добавление.** Запросить название (2–100 символов) и количество (целое 1–1 000 000). При совпадении нормализованного названия увеличить остаток, не создавая дубль. При ошибочном вводе объяснить причину и повторить тот же вопрос.
6. **Списание.** Предложить существующие товары кнопками, затем запросить количество. Не допускать отрицательный остаток; при нехватке сообщить доступное количество и повторить вопрос. Нулевой остаток сохранять. Для пустого склада показать указанное сообщение.
7. **Остатки.** Поддержать кнопку и `/list`; показать позиции по алфавиту, включая нулевые остатки, число позиций и суммарное количество. Для пустого склада показать указанное сообщение. Разбить длинный вывод на сообщения не длиннее 4000 символов.
8. **Поиск.** Поддержать кнопку с запросом и `/find <часть названия>`. Искать подстроку без учёта регистра; показать найденные остатки либо «Ничего не найдено».
9. **Удаление.** Предложить товары кнопками, запросить подтверждение «Да, удалить» / «Отмена». Удалять только после подтверждения; записать удаление и отрицательный остаток в историю.
10. **История.** Записывать добавление, списание и удаление: пользователя, название, изменение количества и время. Показывать последние 20 операций в заданном формате.
11. **Приемка и документация.** Проверить сценарии из критериев приемки: добавление, объединение дубля, запрет списания сверх остатка, повтор ввода после ошибки, сохранность данных при повторной инициализации, отказ неразрешенному пользователю и запуск по README. Проверить граничные/нетекстовые сообщения и целостность транзакций.

## Порядок приемочной проверки

- [ ] Создать товар и увидеть его в остатках.
- [ ] Повторно добавить вариант названия с другим регистром/лишними пробелами; остаток увеличился, дубль отсутствует.
- [ ] Попробовать списать больше остатка; остаток не уходит в минус, диалог продолжается.
- [ ] Ввести неверное количество и проверить причину и повтор того же шага.
- [ ] Повторно открыть SQLite после перезапуска/инициализации; данные сохранены.
- [ ] Проверить сообщение об отказе для ID вне `ALLOWED_USERS`.
- [ ] Установить зависимости и запустить бота по README с настроенным `.env`.
- [ ] Проверить `/cancel`, переключение меню, нетекстовый ввод, поиск, подтверждение удаления, историю и разбиение длинного списка.
